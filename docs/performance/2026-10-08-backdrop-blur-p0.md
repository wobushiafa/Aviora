# BackdropBlur P0 升级与复测 · 2026-10-08

## 交付与决定

- 新增 `RenderScale`（0.25–1，默认 1）。默认保留原始 cropped Surface snapshot + 直接滤镜绘制路径；不自动降低画质。
- `RenderScale < 1` 时，将当前背景的指定区域直接采样并模糊到一个小工作 Surface，再线性放大合成。避免先做全分辨率裁剪复制，也避免两级输入/输出 Surface。GPU 输入保持在 GPU；CPU 后端使用 raster Surface。
- sigma 按实际取整后的工作纹理宽高调整，保留 DIP 半径含义及 3×sigma 外扩输入。圆角和边框保持原始分辨率。
- 仅缓存工作 Surface、滤镜等资源，每次渲染都读取当前背景；不缓存背景像素，不共享不同面板的输入，保持后绘制面板采样先绘制面板的顺序。
- 工作 Surface 创建失败或 GPU 输入缺少有效 context 时，回退原始全分辨率采样路径。
- Demo 新增 1 / 0.75 / 0.5 采样选项，与圆角和半径调节配合比较。

## 为什么没有默认启用局部全分辨率 Surface

先后验证了两级 Surface 原型、单 Surface 原型和交付版本。两级原型增加了纹理/快照与绘制步骤，普通 DPI、多面板场景出现明显回退。单 Surface 在降采样时较合适，但全分辨率局部工作路径在多面板场景仍更贵，因此实验强制开关没有进入交付控件。

最终逐帧交错测量中，200% DPI 半分辨率的配对额外耗时中位数 **4.80 → 2.54 ms（下降约 47%）**，平均场景总耗时 **9.76 → 7.43 ms（下降约 24%）**，P95 **16.59 → 13.12 ms**。达到重点高 DPI 场景额外成本降低 30% 的候选目标。

普通 DPI 多面板的 0.5 采样收益较小，9 个小面板没有稳定收益。建议高 DPI / 较大模糊区域试用 0.5；密集小面板先保持默认，再评估后续共享背景方案。不能将采样比例直接换算成耗时比例。

默认版本平均场景总耗时与原实现相差约 0–3%。该差异仍含系统/驱动噪声，不能视为严格的无回退证明；默认实现保留原始截图与绘制调用，GPU 对照逐像素一致。4K 默认列额外中位数的差异比总耗时差异更大，也说明同步背景基线与分位数受噪声影响。

单面板托管分配：原实现/交付默认 **256 B/帧**，降采样 **360 B/帧**；降采样增加约 **104 B/面板/帧**。4 个面板约 832 → 1248 B/帧；9 个约 1792 → 2728 B/帧。此次升级改善高 DPI 渲染成本，未降低托管分配。

## 方法与边界

- 与[首轮报告](2026-10-08-backdrop-blur.md)相同机器、Avalonia 12.1、.NET 8 Release、真实桌面 Skia OpenGL GPU context；Surface 验证为纹理图像。未严格确认具体物理 GPU 适配器。
- 将修改前控件保存在独立 Release 输出目录。探针通过独立 AssemblyLoadContext 加载原控件及实验原型，共享 Avalonia/Skia 类型；调用实际生产绘制操作，不复制模糊实现。
- 6 个场景 × 5 个版本/参数 × 3 轮 × 120 帧 = **10,800 个计入统计的场景帧**，各有相邻无效果背景帧。每版本每轮另预热 20 帧。
- 同一场景各版本保留独立 Surface/操作资源，计入统计的帧以逐帧随机顺序交错执行；场景组每轮也打乱顺序，减少较长时间负载漂移。每版本首个统计帧紧随其自己的预热块。
- 每帧使用 `GRContext.Flush(true, true)` 等待完成。测量仍包括 GPU/驱动/同步成本，不是纯 shader 时间，也不是整页 FPS。
- 不含 Border、布局、绑定、合成、窗口呈现/VSync 和前景。实际 Demo GPU 截图验证用于检查集成效果，没有宣称达到某个呈现 FPS。
- 本次交错版本同时保留多个 Surface，资源负载与首轮顺序探针不同。只在本次同条件内比较版本，不能把绝对数字与首轮报告直接相减。
- 原生/GPU 工作集未做逐版本峰值采样。小工作纹理和滤镜可能增加 GPU 资源；托管分配数据不能代表总内存。
- 探索数据（compare、compare2、final-compare）保留，用于说明迭代，正式结论使用 interleaved-results。

## 画面与集成验收

- 全量控件测试 **206/206** 通过，其中 BackdropBlur **24 项**：采样范围校验、不同 DPI 的模糊扩散、不对称圆角、Surface 边缘无暗边/透明边、参数/背景刷新，以及已有边框与零半径回归。
- **48 组 GPU 对照**：sigma 4/12、DPI 100/125/200%、旋转 0/15°、分数位置、不对称圆角、采样 1/0.75/0.5/0.25。每组还复用操作改变背景及 opacity，再恢复原始画面。
- 默认 1 的 12 组不透明与半透明 GPU 画面均与原实现完全一致。0.75 / 0.5 的整张图平均色阶差约 0.28（包含未变化背景），最大单通道差分别为 16 / 20。该平均数不能代替局部画质评价。
- 0.25 的最大通道差为 84，小半径下细节损失明显；API 支持，Demo 不将其列为常用档位。
- 实际 Demo 在 GPU 上完成 1 → 0.5 → 0.75 的双向选择与 24 → 64 → 8 圆角切换，三张截图视觉检查通过，模糊可见、前景清晰。
- net8.0/net10.0 控件、Demo 与性能探针构建通过，无警告/错误。
